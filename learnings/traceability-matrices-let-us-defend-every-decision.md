# Traceability matrices let us defend every decision

## What happened

In Prosit 1 we built traceability chains (User problem → User need → Requirement → UX decision → Figma screen) and a screen-to-requirement matrix. In Prosit 2 we extended the chain to the models: Requirement → Figma screen → Use case → Flowchart → Sequence messages, for 12 rows (R01 to R12).

## What we learned

- Each row is a decision a panel can challenge, and we could answer by pointing at the problem, the requirement ID and the exact diagram element.
- Reading the matrix *down* a column shows gaps: a requirement with no screen, or a screen with no requirement.
- Numbering sequence messages (SD1 21 to 27) made rows precise instead of "see SD1".
- Keeping the same requirement IDs from Prosit 1 meant nothing had to be renamed when the models came.

## Do this next time

Start the matrix with the requirements, not at the end. Keep IDs stable across deliverables, number diagram messages, and check columns for blanks before submitting.
