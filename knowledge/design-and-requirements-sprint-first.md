# Design and requirements sprint first

A common problem: developers sit idle because the UI/UX designs are not ready. The lecturer's answers:

- **Make the first sprint about thinking, not building**, if the client agrees. Everyone does requirements analysis together for the first two to four weeks: designers, front end, back end and AI. The team refines and approves the user stories. Each approved story goes to the designers to work on. Implementation starts in the next sprint.
- **Designers work one step ahead.** In later sprints they design upcoming stories while developers build the current ones. If a design turns out to be technically hard, the developers raise it at stand-up. The designers change it, and the team agrees and moves on.
- **Developers don't wait.** While designs are in progress, front-end developers set up the project: framework, dependencies, error handlers. Back-end developers can build against agreed API endpoints.
- **Include developers in design reviews.** This stops designers creating things that cannot be built.
- **A design-only phase is possible for big projects.** He once had five designers work alone for three weeks before the full team joined. The Scrum Master and product owner decide this, with the client's agreement.
- **Hold separate design meetings.** These are dedicated sessions between the designers, the Scrum Master and the product owner.

## Use it in the capstone

Our timeline is short (09 Nov – 18 Dec), so plan sprint 1 as requirements, UX and architecture (personas, user stories, C4 context). Build from sprint 2 onward, with UX staying one story ahead.
