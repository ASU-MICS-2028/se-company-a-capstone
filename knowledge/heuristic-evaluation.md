# Heuristic evaluation

A **heuristic evaluation** is an expert inspection: a few evaluators check an interface against a list of rules of thumb ("heuristics") and log every violation. It needs no users, so it is cheap and quick, and it catches obvious problems before user testing.

Nielsen's ten usability heuristics (paraphrased):
1. Show system status.
2. Match the real world (users' language).
3. User control and freedom (undo, exit).
4. Consistency and standards.
5. Error prevention.
6. Recognition rather than recall.
7. Flexibility and efficiency of use (shortcuts for experts).
8. Aesthetic, minimalist design.
9. Help users recognise, diagnose and recover from errors.
10. Help and documentation.

Harte et al. used heuristic evaluation in Phase 2 with small multidisciplinary groups. They clustered the problems they found by heuristic, so each could be tracked through the design cycle. The concurrency-teaching-tool dissertation evaluated its GUI the same way.

Limits: experts are not real users. It misses context-specific problems, so follow it with user testing.

## Use it in the capstone

Run a one-hour heuristic review of our high-fidelity wireframes before Milestone 2. Log each issue with its heuristic number and a [severity rating](usability-problem-severity-rating.md), and fix the high-severity ones in the next sprint.
