# Where UX sits in the lifecycle

The lecturer asked the class where user experience belongs among the lifecycle stages. Answers included requirements specification and design/analysis. His conclusion: UX sits **largely in requirements specification**, overlapping with design and analysis, but it **percolates down** into every later stage.

- In requirements, you identify all users and their needs.
- In design, you analyse how well the requirements serve those users.
- In implementation and testing, you build and test against those user requirements.
- In monitoring and maintenance, fixes still refer back to the user requirements.

So UX is not a one-off activity or a coat of paint at the end.

## Use it in the capstone

Show UX in every deliverable, not just the UX doc: user-linked requirement IDs, user-focused C4 context view, usability tests in the test plan, and UX findings in the paper.
