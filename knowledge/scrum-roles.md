# Scrum roles

A Scrum team is small (typically 10 or fewer): **one Product Owner, one Scrum Master, and Developers**. The 2020 Scrum Guide calls these *accountabilities*. The team is cross-functional (has all the skills needed) and self-managing (decides who does what).

**Scrum Master (SM)**: accountable for the team's effectiveness and for Scrum being done properly.
- Knows and has practised Scrum; coaches the team on its principles.
- Facilitates the events (also called **ceremonies**) and keeps them within their timebox.
- Causes impediments to be removed (solves them, or decides to ignore them).
- Protects the process so work isn't done arbitrarily; helps the PO with backlog technique.

**Product Owner (PO)**: accountable for maximising the product's value.
- Sets the Product Goal, writes and **orders** the backlog, keeps it visible.
- One person, not a committee. Others change the backlog by persuading the PO.
- Represents stakeholders inside the team and engages often with the client.

**Developers** (several)
- Build the usable Increment, from UI design through testing.
- Own the Sprint Backlog, uphold the Definition of Done, adapt the plan daily.

Key rules: **no hierarchy** and no sub-teams. **Accountability is shared**: if a sprint fails, the whole team is accountable. If the PO or SM also build features, they count as Developers for that work, which is normal in a six-person team.

From the lecturer's own Scrum team: stable teams work best; new members are vetted so they don't become a point of failure; backups are trained as **mentees** who observe a run or two before stepping in (including a backup SM).

## Use it in the capstone

The documentation package requires a role assignment. Name the PO and SM for each sprint, everyone as a Developer, plan a backup for each role, and note rotations in the retro summary.
