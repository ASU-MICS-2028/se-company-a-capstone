# Usability problem severity rating

Finding problems is not enough. You also need to know which to fix first. A **severity rating** scores each problem by how likely it is to hurt users and how badly.

Harte et al.'s three steps for early feedback, gathered with Likert scales after each use case scenario:
1. **Cluster** the problems by heuristic, scenario by scenario.
2. **Relate** each problem to the Likert item it affects.
3. **Calculate severity** from the median score on that item, giving each problem a rating.

A simpler scale for later testing: 0 not a problem, 1 cosmetic, 2 minor, 3 major, 4 catastrophic (blocks the task or risks harm). Severity rises with frequency, impact and persistence.

Prosit 1's day-5 evaluation asks for at least 3 problems, each with its severity, a proposed fix, and the change actually made.

## Use it in the capstone

Keep a usability issue log in the repo (issue label `ux`) with a severity field. Report "found, fixed, remaining by severity" in the paper's Evaluation section.
