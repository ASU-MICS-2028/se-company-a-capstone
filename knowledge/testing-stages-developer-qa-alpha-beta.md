# Testing stages: developer, QA, alpha and beta

The lecturer described testing as a chain of hand-offs:

1. **Developer testing** - the developer tests their own work, then pushes it on.
2. **QA testing** - a dedicated QA officer tests it again.
3. **Alpha testing** - done in-house, on an internal or production-like server.
4. **Beta testing** - done by external people using the product for a period (for example two or three months, like the free beta versions of antivirus tools). The company gathers data and issue reports to check that the product is useful and works as intended, and fixes problems quickly.
5. **User testing** before final deployment - let users use it and get excited, so that they are happy to pay once it is priced.

Only after approval do you prepare assets for deployment.

## Use it in the capstone

Our test plan can mirror this chain: unit tests by each developer, peer QA review, an internal demo (alpha), and a short pilot with a few target users (beta) before the 18 December presentation.
