# Capstone deliverables checklist

Everything the brief says we must hand in. Tick it off before 18 Dec 2026.

**Before building**
- [ ] Concept note (13 Nov)
- [ ] Project proposal, 2–4 pages (Milestone 1, 14 Nov). Implementation may not start until it is approved. See [Capstone proposal contents](capstone-proposal-contents.md).

**A. Software prototype (executable system)**
- [ ] Backend logic (API, ML pipeline, databases, etc.)
- [ ] Frontend interface (web, mobile or terminal UI)
- [ ] Integration between components
- [ ] Intelligent or data-driven part visibly working
- [ ] Git repository meeting the [repo requirements](capstone-repo-requirements.md)

**B. Documentation package**
1. Requirements: functional; non-functional (performance, usability, privacy, security, availability, reliability); user stories with acceptance criteria
2. UX: personas; system workflows; low- and high-fidelity wireframes; usability considerations
3. Architecture and design: architecture diagrams (C4 recommended); component interaction and data flow diagrams; database schema or data structures; programming model justification; tech stack rationale; deployment strategy and infrastructure assumptions
4. Agile artefacts: Scrum board export or screenshots; sprint backlog and burndown charts; sprint retrospective summaries; role assignment (Scrum Master, Product Owner, Developers)
5. Quality evidence: reliability and availability computations for all or some components; test plan (unit, integration, system, acceptance); automated tests (optional bonus); risk assessment and mitigation plan

**C. ACM research paper**, 6–10 pages. See [ACM paper structure](acm-paper-structure.md). Include an AI Use Declaration.

**D. Presentation and demo.** See [Capstone presentation format](capstone-presentation-format.md).

**Uploads (GitHub Classroom and Canvas):** repo link with the documentation package; compiled software artefacts; PDF of the ACM paper; presentation slides.

## Use it in the capstone

Copy this list into the repo's docs index or the Scrum board as one card per line. Each card needs an owner and a due date.
