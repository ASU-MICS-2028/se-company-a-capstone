# The Scrum cycle at a glance

The lecturer's walk-through, using an automated menu screen for an inclusive cafeteria:

1. **Product goal** - short and specific, with the key words in it: "an inclusive cafeteria". It states the value added (here, inclusivity).
2. **Product backlog** - the itemised to-do list for the whole product, essentially the requirements.
3. **Sprint planning** - pick backlog item(s), research how to deliver them, agree the plan and **commit to the sprint goal**.
4. **Sprint backlog** - break the item into tasks: buy a large enough screen (a small one isn't inclusive), build the software to add and remove menu items, decide where to mount it.
5. **The sprint** - an engineering loop where rigour is strictest: daily scrum, build, QA testing, and **CI/CD** (continuous integration and delivery: merging each change into the running system).
6. **Increment** - a potentially releasable piece of working software, like a software update.
7. **Sprint review** - show it to stakeholders for feedback.
8. **Retrospective** - the team alone reflects on how it worked.
9. **Backlog adaptation (refinement)** - add fixes (for example, "make the font bigger") and unfinished work back to the backlog, then plan the next sprint.

Advice: keep each sprint to about two backlog items (three for a bigger team), so it stays focused. Sprints are commonly one or two weeks.

## Use it in the capstone

Mirror these nine steps as headings in each sprint record, so the Scrum deliverable shows the full cycle every time.
