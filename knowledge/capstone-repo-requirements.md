# Capstone repository requirements

The brief says the Git repository **must contain**:

- [ ] Source code
- [ ] Commit history (real, incremental commits by the whole team)
- [ ] Issue tracking
- [ ] A branching strategy (documented, and visible in the history)
- [ ] A documentation folder (holds the documentation package)
- [ ] Build and run instructions
- [ ] Testing artefacts (test plan, test code, results)

Submission is via **GitHub Classroom + Canvas**: the repo link with the documentation package, compiled software artefacts, the paper PDF and the slides.

The rubric scores "Code quality and repository" at 5%. Exemplary means "clean, well-structured code with Git best practices". "Team collaboration" (5%) is judged on effective use of tools such as Trello or Jira, and GitHub issues and projects count as evidence too.

## Use it in the capstone

Agree the branching strategy now (for example, short feature branches into `main` through pull requests) and write it in the README. Link every pull request to an issue. Keep build instructions tested on a clean machine before 18 Dec.
